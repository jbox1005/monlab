# 코드북 (Codebook)

사내 반입 데이터의 모든 코드값 정의. `schema/place.schema.json` 과 짝을 이룬다.

---

## 1. 필드 채움 등급 (중요)

요청된 필드 중 상당수는 **어떤 공개 API로도 수집되지 않는다.** 반드시 이 구분을 전제로 운영해야 한다.

| 등급 | 의미 | 해당 필드 |
|---|---|---|
| **AUTO** | 수집 파이프라인이 자동으로 채움 | 상호, 주소, 좌표, 전화, 인허가 정보, 구역, 카테고리, 두 기준점 도보거리, 딥링크 |
| **SEMI** | 카카오 카테고리·영업정보에서 부분 추출, 검수 필요 | 메뉴, 가격대, 영업시간, 웨이팅, 분위기 태그, 주류판매, 주차 |
| **MANUAL** | **사람이 입력해야 함. 자동 수집 불가** | 예약가능, 룸유무·수용인원, 테이블링, 콜키지·금액, 단체수용인원, 분위기(mood), 대표메뉴 지정 |

> 행안부·카카오·구글 어디에도 콜키지·룸·테이블링 정보는 없다.
> 이 필드들은 최초 1회 수동 입력 후 사내 사용자 제보로 갱신하는 것을 전제로 설계했다.

## 2. 목적 뱃지 (`purpose_badges`) — 복수 부여 가능

| 코드 | 표시명 | 자동 부여 조건 |
|---|---|---|
| `LUNCH` | 점심식사 | 점심 영업 O + 카페 카테고리 아님 + 유흥주점 아님 |
| `CAFE` | 식후 카페 | 카페/디저트(L1=`CAF`) 카테고리 보유 |
| `DINNER` | 회식장소 | 주류판매 O + (룸 O 또는 단체수용 8인↑ 또는 `단체석` 태그) |

**가격은 뱃지 조건에 넣지 않는다.** 22,000원짜리 점심 반상 같은 정상 케이스가 탈락하기 때문.
점심 예산 필터는 `price_range.lunch_per_person` 으로 UI에서 처리한다.

규칙 수정은 `config/rules.json` 의 `purpose_badges[].auto_rule` 에서. 코드 수정 불필요.

## 3. 메뉴 카테고리 (`categories` / `primary_category`)

사용자 탐색 경로는 **대분류(L1) → 메뉴 카테고리(L2) → 가게** 3단이다.
`out/taxonomy_index.json` 이 이 3단 트리를 미리 만들어 둔다.

| L1 | 명칭 | L2 |
|---|---|---|
| `KOR` | 한식 | 백반/찌개, 칼국수, 만두, 족발/보쌈, 냉면, 국밥/탕, 고기구이, 곱창/막창, 전/한정식, 해물/찜 |
| `JPN` | 일식 | 이자카야, 스시/회, 돈카츠/덮밥, 라멘/우동 |
| `CHN` | 중식 | 짜장/짬뽕, 양꼬치, 마라/사천, 중화요리 |
| `WST` | 양식 | 파스타/피자, 스테이크, 브런치/버거 |
| `SNK` | 분식 | 김밥/떡볶이, 국수/우동 |
| `ASN` | 아시안 | 베트남, 태국/기타 |
| `BAR` | 주점 | 호프/맥주, 포차/실내포차, 와인바, 위스키/칵테일, 전통주점 |
| `CAF` | 카페/디저트 | 커피, 베이커리, 디저트, 차/전통찻집 |

- 한 가게가 **여러 L2 를 가질 수 있다.** (예: 을지로빈대떡 = `KOR_JEON` + `BAR_TRAD`)
- `primary_category` 는 최고 점수 L2 하나.
- 분류 점수: 대표메뉴 매칭 **2점**, 일반메뉴/상호 매칭 **1점**, 인허가 업태 **0.8점**.
  업태가 낮은 이유는 "까페"가 커피·베이커리·디저트를 구분하지 못하기 때문.
- 카테고리 트리와 키워드 사전은 `config/taxonomy.json` 에서 수정.

## 4. 3상태 코드 (예약 / 룸 / 테이블링 / 콜키지 / 주차)

| 코드 | 의미 |
|---|---|
| `YES` | 가능 |
| `NO` | 불가 |
| `COND` | 조건부 (예: 6인 이상만 예약, 룸 이용 시에만 콜키지) |
| `UNKNOWN` | 미확인 — **기본값** |

`COND` 인 경우 반드시 `*_note` 에 조건을 적는다. (`reservation_note`, `corkage_note`)

- `corkage_fee`: 병당 원 단위. **`0` = 콜키지 프리**, `null` = 금액 미확인
- `waiting_apps`: `테이블링` / `캐치테이블` / `나우웨이팅` / `현장only`

## 5. 웨이팅 (`waiting.level`)

| 코드 | 표시명 | 기준 |
|---|---|---|
| `NONE` | 없음 | 대기 거의 없음 |
| `LOW` | 보통 | 피크에만 5~10분 |
| `HIGH` | 많음 | 피크 15~30분 |
| `EXTREME` | 매우많음 | 상시 30분 이상, 웨이팅 필수 |
| `UNKNOWN` | 미확인 | 기본값 |

`waiting.peak_time` 은 `HH:MM-HH:MM` 형식.

## 6. 분위기

- `vibe.mood` — 닫힌 집합 1개: `캐주얼` / `정갈` / `시끌벅적` / `모던` / `노포` / `접대용`
- `vibe.tags` — 화이트리스트 복수 선택. 자유입력하면 필터가 깨진다.

  `조용한` `시끌벅적` `모던` `레트로` `노포` `깔끔한` `아늑한` `가성비` `고급스러운`
  `단체석` `1인석` `야외석` `루프탑` `뷰맛집` `인테리어좋음` `혼밥가능` `접대용` `데이트`

화이트리스트 수정은 `config/rules.json` 의 `vibe_tags.allowed`.
`build.js` 가 목록에 없는 태그를 자동으로 걸러낸다.

## 7. 거리 (`distance`)

두 기준점 각각에 대해 산출한다.

| 키 | 기준점 | 주소 |
|---|---|---|
| `ibk_hq` | IBK기업은행 본점 | 서울특별시 중구 을지로 79 |
| `ibk_finance_tower` | IBK파이낸스타워 | 서울특별시 중구 을지로 82 |

| 필드 | 의미 |
|---|---|
| `straight_m` | 직선거리(m) |
| `meters` | **도보 추정거리** = 직선거리 × 1.35 (도심 격자도로 우회계수) |
| `walk_min` | 도보 추정 소요분 = 거리 ÷ 67m/분 + 횡단보도 보정 |
| `method` | `estimate`(추정) / `api`(보행경로 API) |

계수는 `config/anchors.json` 의 `walking` 에서 조정.
두 건물이 을지로 79/82 로 마주보고 있어 대부분 업소에서 두 값 차이는 1~2분 이내다.

## 8. CSV 반입 규칙

`out/places.csv` 는 사내 프로그램 반입용 평탄화 파일이다.

- 인코딩: **UTF-8 with BOM** (엑셀 한글 깨짐 방지)
- 다중값 구분자: `|` — 예: `purpose_badges` = `LUNCH|DINNER`
- 메뉴 직렬화: `이름~가격|이름~가격` — 예: `바지락칼국수~10000|들깨칼국수~11000`
  - 가격 미상이면 `이름~` (물결 뒤 빈칸)
- 불리언: `Y` / `N` / 빈칸(미확인)
- 컬럼 순서는 `scripts/lib/flatten.js` 의 `COLUMNS` 배열이 정본

## 9. `data_status`

| 코드 | 의미 |
|---|---|
| `SAMPLE` | 스키마 예시용 가공 데이터. **실재 업소 정보가 아님** |
| `DRAFT` | 자동 수집만 완료. MANUAL 필드 미입력 |
| `VERIFIED` | 수동 검수 완료 |

사내 프로그램에 반입할 때는 `SAMPLE` 을 반드시 제외하거나, 별도 테스트 환경에만 넣는다.
